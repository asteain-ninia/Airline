# Create Aeronautics: Airline for MineColonies

MineColonies の村どうしを、飛行機(Create Aeronautics の船)で結んで物資を運ぶ MOD。**作りかけ**で、いまあるのは、飛行場と飛行士、ブイの空路網と近い村どうしの直行便、機体の自動操縦、荷の積み降ろしと定時便、2 機目からの交通整理(迂回つき)、飛行場のレベル 1〜5、機体の型(3 種)と建造・整備、燃料と遭難・救助、取りに行くだけの便、飛行士の専用の見た目。**版は 0.21.0。** 版ごとに足したものと変えたものは [CHANGELOG.md](CHANGELOG.md)。この README の下の方は、まだ 0.11 のころの書き方のところがある。

> **決まり: 版が 1.0.0 になるまで、後方互換は一切考えない**(2026-10-16 のご裁定)。古いセーブ・古い設定・古い型を読むための仕掛けは作らない。形式を変えるときはただ変え、前の版で作った物が壊れるなら、そう書く。本文は `..\CLAUDE.md`。**1.0.0 にするときは、この決まりを消す**(`gradle.properties` の `no_backcompat_before` が残ったまま 1.0.0 以上にすると、ビルドが止まる)。

- MOD の ID は `airline`、命令は `/airline …`、Java のパッケージは `com.asteain.airline`。Java の中で ID を文字列で書いているのは `Airline.MOD_ID` の 1 か所だけ。名前の経緯は下の「名前について」。
- Minecraft 1.21.1 / NeoForge 21.1.x / MineColonies 1.1.1403。ライセンスは GPL-3.0(MineColonies と同じ)。
- **サーバーと、参加する側の両方に入れる。** ブロックと、MineColonies の建物・職業の登録を足すため。
- 計画と取り決めは `..\ColonyPatchServer\design\`(全体の状態は `roadmap-user-decisions-2026-10-06.md` の冒頭。段階ごとの記録は `airfield-2026-10-07\`、`beacon-network-2026-10-07\`、`cargo-2026-10-07\`、`rulings-apply-2026-10-11\`、`pilot-skin-2026-10-11\`、`traffic-2026-10-11\`、`levels-2026-10-11\`、`block-art-2026-10-12\`。画面で確かめる順番は `user-checklist-2026-10-11.md`)。
- `build\libs\old-name\` の `airroute-*.jar` は、改名より前の古い jar。`build\libs\not-a-release\` は、作業の途中のビルドが同じ名前で上書きしてしまった jar。どちらも使わない。
- 見た目を確かめるページ(立体ビューアーと全体の紹介)は `..\ColonyPatchServer\design\review-2026-10-11\`(`python build_review.py` で作り直す)。

## この保管場所について

- **この MOD のプログラム・文書・試験は、ほぼすべて生成 AI が書いた**(Anthropic の Claude を、Claude Code で動かした)。ブロックの絵と模型、飛行士の見た目は、OpenAI の Codex が描いた。作者は、何を作るかを決め、出来上がった物をゲームの中で確かめ、機体の形をゲームの中で組んだ。
- ライセンスは GPL-3.0(本文は [LICENSE](LICENSE)。jar の中では `LICENSE_airline.txt`)。
- 飛行士の見た目(`src/main/resources/assets/minecolonies/textures/entity/citizen/default/pilot*.png` と `entity_icon/` の同じ名前の絵)は、MineColonies(GPL-3.0)の村人の見た目に、服を描き足したもの。
- **非公式の追加 MOD。** MineColonies・Create・Create Aeronautics・Sable の作者に、この MOD のことを問い合わせないでほしい。
- 設計の記録(下の `..\ColonyPatchServer\design\`)と、コンパイルや試験に使うほかの MOD の jar は、この保管場所に入っていない。ソースから組み立てるときは、`build.gradle` の `sharedLibs`・`sharedTestJars`・`journeyMapApiJar` の場所に、同じ版の jar を置く。組み立てた jar は Releases に置いてある。

## いまできること

### 飛行場(建物)と飛行士(職業)

- **飛行場。** 小屋ブロック `airline:blockhutairfield`。レベルは 1 から 5。建築ツールでパック「Airline」を選んで置く。鏡写しや回転で置いてもよい(台の位置と、機体の向きが付いてくる)。
    - **一つの大きな建物**。敷地は、どのレベルも 34 × 25(高さ 9 まで)。レベル 1 は、西の半分の北に、機体が垂直に離着陸する台(13×13)と丸石の前庭、南に寄棟屋根の格納庫。東の半分は土の空き地。見た目は MineColonies の Original パックのレベル 1 の建て方(オークの柱と板壁、柵の窓、丸石の階段の軒をもつ寄棟屋根、丸石の床)。
    - 格納庫の中に、**輸出用の棚 4 つ**、**輸入用の回収箱(MineColonies の Stash)1 つ**、飛行士の机がある。どれも設計図に含まれていて、建築家が建てる。
    - **レベル 2** で、同じ敷地のまま建て替える(Original パックの建物のレベル 1→2 に合わせた): 格納庫は壁が 1 段高く、窓がガラス板に、軒が石レンガの階段に、梁からランタン、裏口にひさし、棚が 6 つに。東は前庭になり、**来客の台**(よその機体が降りる台)と、来客のあずまや(棚 2 つ)。小屋ブロック、回収箱、前からの棚、母港の台は動かない。
    - **台には 1 機。母港の台は、その機体のために空けておく。** だから、自分の機体があるレベル 1 の飛行場には、よその機体は降りられない。お互いに荷を運び合う 2 つの村は、どちらもレベル 2 が要る。
    - **レベル 3〜5** は、同じ敷地・同じ 2 つの台のまま、建物を材料ごと建て替える(Original パックのほかの建物と同じ順): 3 はトウヒと瓦屋根(来客のあずまやが、壁のある来客の小屋になる)、4 はダークオークと木組みの壁(前庭が石レンガに、建物の間に屋根つきの渡り)、5 はレンガ(柵がレンガの塀に)。瓦と木組みは Domum Ornamentum のブロック。輸出用の棚は、レベルごとに 4 つずつ増える(4・8・12・16・20)。
    - 改築しても、小屋ブロック、回収箱、前のレベルまでの棚は動かない(中の品物が残る)。建物の高さは、レベル 2 から変わらない(航路が台の 16 ブロック上から出るので、床から 8 段まで)。
    - 設計図は `python tools/make_blueprint.py` が、レベル 1 から 5 を作る(`--show` で層ごとの略図が出る)。
- **飛行士。** 飛行場に 1 人。機体を飛ばし、**飛行場の棚と機体の荷室の間で、荷を歩いて運ぶ**。倉庫と飛行場の間は、配達人が運ぶ。専用の見た目(飛行帽、ゴーグル、襟巻き)がある。参加する側で飛行士が見えたときに不具合が出たら、`config/airline-common.toml` の `pilotSkin` を false にすると、普通の村人の見た目に戻る。
- **輸出の表。** 飛行場の窓のタブ(MineColonies の「最低在庫」の画面を流用)で、品物ごとに「倉庫に残すスタック数」を決める。
- **時刻表。** 飛行場の窓のタブ。「次に出る便」(出発までの残り、行き先、着く見込み)と「次に来る便」が出る。窓を開いている間、残り時間は減っていく。
- **台帳。** 「どの村が、どの品物を、いくつ欲しがっているか」。命令で入れる分と、飛行場が自分の村の「だれも満たせない依頼」(プレイヤーに回っているもの。品物を 1 つ名指ししている依頼だけ)から読み取って載せる分がある。依頼そのものには手を付けない。
- **集積。** 表にある品物について、ほかの村(**空路網で行ける村だけ**。0.11.4)が欲しがっていて、倉庫に「残す分」を超える在庫があるとき、足りない分を MineColonies の依頼の仕組みに要求する。配達人が倉庫から飛行場の棚(輸出用)へ運ぶ。
    - 自分の村でその品物が足りていない(だれも満たせない依頼がある)あいだは、輸出しない。
    - 依頼は品物ごとに 1 件、1 スタックまで。届いたら次を出す。
    - 倉庫のほかに割り当てられた依頼(職人、再試行、プレイヤー)は取り消す。「欲しい」が消えたら取り消す。
    - 輸出用の棚の中身は、配達人の回収で倉庫へ戻らない。

### ブイと空路網

- **ブイ。** ブロック `airline:buoy_1`〜`buoy_3`(数字が等級)。置いた座標で、そのディメンションの空路網に載る。壊すと外れる。支えは要らない。見た目は Codex の設計(帆布の浮き袋の下に、木枠の灯室。等級は輪郭で見分ける。`python tools/make_buoy_art.py` が作る)。レシピは仮。
- **つながり方は、MineColonies のコロニーの看板に倣っている。**
    - 置くだけで、届く範囲のブイや飛行場の台と、自動で航路がつながる。手で結ばない。**2 つの地点は、届く距離の和より近ければつながる。** ブイの届く距離は、等級ごとに 48 / 96 / 192 ブロック(3・6・12 チャンク)。
    - **飛行場の届く距離は、建物のレベルで伸びる: レベル 1〜5 で 8・10・12・16・20 チャンク**(128〜320 ブロック)。MineColonies の設定から決まる(レベル 1 = タウンホールどうしの最低の距離 `minColonyDistance`、レベル 5 = 村の最大の半径 `maxColonySize`)。空路 MOD の設定 `airfieldReachChunks1`〜`5` で、決め打ちもできる(0 が自動)。この距離は、ブイとのつながりと、下の「大マップ」の境目をまたいだすぐ隣の村(レベル 1 どうしで 16 チャンク未満)に使う。
    - **飛行場どうしは、「大マップ」の単位で、ブイなしの直行便でつながる(0.11.0。0.11.1 で、ご裁定のとおりに直した)。** 世界を、原点から 128 チャンク四方(レギオン 4 × 4。2,048 ブロック四方。設定 `largeMapChunks`)のます目に切り、飛行場は、レベル 1〜5 で、自分のます目の周り 0・1・2・3・4 枚まで届く(1×1 〜 9×9 枚)。**飛行場のます目は、小屋ブロックの位置で数える。2 つの飛行場は、レベルの高いほうの範囲に相手が入ればつながり、それ以外では、つながらない**(境目をはさんだ、すぐ隣どうしでも)。`largeMapChunks` を 0 にすると、この決まりは切れて、飛行場どうしも、届く距離の和で決まる。数千ブロックの航路でも点検が詰まらないよう、航路の点検は、航路が通るチャンクだけを順に見る(読み込まれていない所は飛ばし、「未検証」のまま。未検証の航路は飛べる)。
    - **届く範囲に点が一つも無い所には、置けない**(「遠すぎます。いちばん近い地点まで N ブロック」と出る)。飛行場の台から、順に伸ばしていく。命令や装置で置いたブイには、この決まりは掛からない。
    - 置いた人に、航路の数(通れる・塞がっている・未検証)と、塞いでいるブロックの場所が知らされる。
    - ブイを素手で使うと、航路の様子と、つながっている飛行場(村の名前と道のり)が出る。
    - 2 つの飛行場の間に道ができたとき、切れたとき、両方の村の管理者に知らせが出る。
- **経路は、台を通り抜けない。** 出発と到着のほかの台は、途中の地点にならない(台の上の空間は、そこで上がり下がりする機体のもの)。台どうしだけでつながっている 3 つの村は、間にブイが 1 つ要る。
- **台の真上を低く通る航路は、使わない。** 台には機体が止まるので、台の中心から横に 13.7 ブロック以内(機体の角までの距離の 2 倍 + 1)を通る航路は、そこで台の床から 15.5 ブロック以上の高さが要る(航路の両端の台そのものは別)。足りない航路は「塞がっている」と同じ扱いになり、ブイを素手で使うと、どの台のせいかが出る。台の上の航路は床から 16.5 ブロックの高さで始まるので、水平か、ゆるい下りなら通れる。ブイを台の床から 8 ブロックほど上に置くと、航路は水平になる。
- **航路の高さ。** 航路は、ブイの真上 9 ブロック、**飛行場の台の真上 18 ブロック**を通る(既定値。`waypointHeight`・`airfieldWaypointHeight`)。機体は、台の真上へ 18 ブロック上がってから航路に乗るので、飛行場の屋根や、台より 10 段高い建物までは、航路を塞がない。
- **検証。** 航路ごとに、機体の通る筒に固いブロックが無いかを調べ、「未検証」「通れる」「塞がっている」を持つ。**台の上で建造中の機体のブロックは、数えない**(0.11.4。建造の場所が、数秒ごとに機体の外寸の範囲を空路網へ届ける。届けが途切れたら、その台の航路を見直す)。飛行場の台の上の、機体が上がり下がりする筒(台の中心から横に 8.5 ブロック、床から 2 段め以上)も一緒に調べる。ブロックが置かれたら、その航路を塞がっている扱いにし、無くなったら調べ直す。
- 決まりと数字は `route/RouteRules.java` にあり、数字は `config/airline-common.toml` で変えられる。

### 飛行機

**飛ぶ部分は、Sable と Create Aeronautics(Simulated を含む)が入っているときだけ働く**(0.21.0 から、ColonyPatch Server は要らない。村人が船の上を歩く・席に座る部分は、この MOD に入った)。 どれかが無ければ、飛ぶ部分だけが止まり(命令は「止まっています」と答える)、飛行場と集積とブイの網は動く。

- **機体。** (0.19.0 から、型は小枝号・雲中号(2026-10-20 に丸太号から改名。中の名前は stratus のまま)・大凪号の 3 つ。**型を指定しないと小枝号**。原型と白帆型は 2026-10-19 に外した〈ご指示「消しといて」〉。本番に原型・白帆型の機体が残っていれば、その機体は飛ばず、建造も進まない(記録に一度だけ失敗が出る。外した型を小枝号として読む逃げ道は 0.19.0 で外した)。こかぜ型は 0.12.0 で外した。以下は 0.11 のころの書き方。)型は 3 つ。どれも外寸 9×9×9 の箱(前後 × 左右 × 高さ。0.11.1 で、左右を 7 → 9 に広げた。飛行場の見た目と、航路の管の太さは、そのまま)の中で、荷室は樽 2 個(54 スタック)。**型を指定せずに建造・呼び出しをすると、こかぜ型になる**(0.11.1。ご裁定。型を覚えていない古いセーブの機体は、原型として読む)。**どのレバーを何に使うかは、型のデータが決める**(下の「型のファイル」)。原型と白帆型は、機械(エンジン 2、歯車、プロペラ 2、バーナー、レバー 5、席)の位置が同じ。
    - `kokaze`(定期船 こかぜ型。0.11.0 で追加、0.11.1 で 3 回目の設計に。**0.12.0 で外した**: 小枝号と入れ替え〈2026-10-15 のご裁定〉。本番に立っているこかぜは、0.12.0 では小枝号として扱われ、造船所が小枝号の形に組み替えようとする): **Codex が、原型を見ずに一から設計して、試験場で飛ばして仕上げた機体。最初に出る型。** エンジン 1 台(機首寄りの甲板)から、アナログ変速機と方向切替ギアを通して、気嚢の外を通る縦の軸で、気嚢の両脇の外に出したプロペラ(32〜256 回転)へ。機械は、全部、気嚢の外。構造のためだけのブロックは無い(木のブロックは 22 個。気嚢は、船体と面でつながっていない)。秒速 7.5 ブロック、その場の旋回 毎秒 59 度、満タンで 160 分、気嚢の容量 125 m³、質量 63.0。1,815 ブロックの直行便(場面 `direct`)が、頼んでから向こうの台に固定されるまで 5 分 40 秒(原型の速さなら 17 分の計算)。1 回目の設計(機械が気嚢の中)と 2 回目の設計(プロペラが気嚢の壁のくぼみ)は、記録に残してある。経緯と数字は `..\ColonyPatchServer\design\aircraft-free-2026-10-13\README.md`。
    - **型のファイル**(`resources/airline_aircraft/<名前>.json`)は、自前の設計(`"format": 2`)だけ(原型の機械のまわりに船体を付けた書き方は、原型と一緒に外した): ブロックのほかに、席、樽、樽の前に立つマス、バーナーとそのレバーと設定値、エンジン(1〜4 台)、推進のレバー(何本でも)、**操作ごとのレバーの値の表**(`drive`: 前進、後進、その場で左右、進みながら左右。任意で、弱い前進・後進・左右、「切」)、少しずつ動かすレバー(`throttles`)、測って決めた操縦の数字(`handling`)。書式の説明は `..\ColonyPatchServer\design\aircraft-free-2026-10-13\codex\FORMAT.md`。
    - 型を足すときは、型のファイルを置き、`flight/AircraftType.java` の `BUNDLED` に名前を足し、`python tools/make_aircraft_blueprints.py` で設計図を作る。外寸に収まらない型、装置の位置がファイルの言うとおりでない型は、読み込まれない。
    - **試験場**(`python tools/bench.py <設計の .json か、型の名前> [--mode static|raw|all|legs|dock] [--leg <ブロック>] [--offset <ブロック>] [--outline <前>x<後>x<半幅>x<高さ>]`。`dock` は、Create Aeronautics の連結器が、プレイヤーなしでつながるかを見る(係留の案のための確かめ)。`--outline` は、試験場の中だけ、機体の枠を広げる(大きい機体を、型にする前に測るため)。`legs` は、型に入っている操縦の数字のままで、自動操縦の課題だけを回す。`--leg` は直進の長さ、`--offset` は、航路を機体の横へずらして始める幅): 専用サーバーが、その機体を 1 機つくり、機体のレバーだけで動かして、測った値を JSON で返す(質量と重心、気嚢、操作ごとの部品の回転数と推力、上昇、速さ、惰性、制動、旋回、自動操縦での直進・角・旋回・位置合わせ。測った値から、`handling` の数字も決める)。MOD にまだ入れていない設計は、サーバーの起動時に `-Dairline.design=<ファイル>` で読ませる(試験場と、`run_batch.py` の `場面@<ファイル>.json` が、そうしている)。試験場のためだけの受け口は `flight/Trial.java`(局面 `TRIAL`)。
- **機体ブロック**(`airline:aircraft`)。機体の甲板の中央に 1 つ。見た目は、甲板のオークに真鍮の方位盤(矢は機首の向き)。小屋ブロックと一緒に、`python tools/make_block_art.py` が作る(絵とモデルは Codex が作った `tools/block_art_painter.py`)。母港、機体の種類、便の進み具合を覚える(船の中のブロックなので、船と一緒に保存される)。地上では機体を世界に固定し、便の間は Sable の読み込みの印を持つ。自動操縦を動かす。
- **台の上での位置合わせ**(0.11.1、0.11.2)。降りる前に、まず台の向きと直角に向いて左右を合わせ、次に台の向きに向いて前後を合わせる。**前後は、機体ブロック(船底の真ん中)を、台の真ん中に合わせる**(重心でなく。重心が浮く力の中心より前にある機体は、機首を下げて浮くので〈こかぜ型は 5.7 度〉、重心で合わせると、船体が後ろにずれて座り、飛行士が降りられないことがあった)。機体ブロックの位置は、その瞬間の値でなく、**「重心 + 重心から機体ブロックまでの前後のずれを 3 秒ほどならした値」**で使う(0.11.2。機体ブロックは重心より 3〜4 ブロック下にあるので、機体が前後に揺れると、その位置も揺れる。0.11.1 では、それを追いかけて位置合わせが収まらず、白帆型が、台の真ん中から 2.3 ブロックずれて降りたことがあった)。**降りていく間も、その位置を保つ**(0.11.2)。前後・左右それぞれ、0.2 ブロック以内(型の数字 `placeWithin`)で「合った」とする。0.11.2 の通し試験では、こかぜは 32 回の着陸で、台の真ん中からのずれ 0.02〜0.28 ブロック(平均 0.13。0.3 を超えた回は無い)。白帆型は 4 回で 0.03〜0.19。原型は 13 回で 0.06〜0.30。**分かっている残り:** 機体ブロックが、台の真ん中より船尾の側へ 0.2 ほど寄って座ると、飛行士が船尾から降りる歩きが通らないことがあり、そのときは、15 秒後に機首の側から降りる(こかぜ型の、長い片道の着陸で出る。同じ位置で、すぐ降りられた回もある)。数字と経緯は `..\ColonyPatchServer\design\rulings-2026-10-14.md` の「着陸の位置合わせ」。
- **自動操縦は、飛行士が席に座っているときだけ働く。** 書くのは、機体のスロットルレバー 5 本の値だけ(プレイヤーが手で動かせる装置)。船に力は加えない。レバーを動かすのは 10 ティックに 1 回まで。
- **前を見て止まる。** 飛びながら、24 ブロック先までの筒に、固いブロックや、ほかの船が無いかを見る。ブロックがあれば、その航路を「塞がっている」にして、一つ前の地点まで戻り、別の経路を探す。無ければ出発地へ戻って着陸し、欠航にする。前も後ろも塞がれたら(または、ほかの船が前にいたら)、その場で高さを保って待つ。
- **何機でも同時に飛べる。** 機体は、離陸の前に「いつ、どこに居るつもりか」の予定を出し、すでに飛んでいる機体の予定と近づきすぎる(上から見て 16 ブロック以内、かつ高さの差 11 ブロック以内)なら、飛行士が席に着いたまま地上で待つ。同じ航路を同じ向きに続けて飛べる。向かい合う 2 機は、片方が通り終わってから出る。
    - 予定が外れて空中で出会ったら、止まって待つ。待っても空かなければ、**迂回する**(一つ前の地点まで戻って、その航路を使わない経路で進む。欠航にしない)。迂回できる航路が無いときだけ、行きの便は出発地へ引き返す(欠航)。プレイヤーの船が航路の上に止まっているときも、同じ。
    - 台に止まっている機体の真上は、近くを通る(隣の台へ行く航路が、そこを通るため。低すぎる航路は、網のほうで最初から使わない)。
    - 決まりは `flight/Airspace.java` と、`flight/FlightController.java` の `free()`(台が空いているか)、`landing()`(降りる台の選び方)、`plan()`(予定の作り方)。試験は 3 機まで。

### 機体の建造と整備

- **建造は、飛行場の窓の「機体」のページから頼む**(0.11.3。ユーザーの指示「建造の制御は飛行場のみの責務」)。型ごとの「建造を頼む」で、飛行場の自分の台の真ん中(十字の交点)に機体ブロックが置かれ、村の建築家へ「機体の設計図を建てる」依頼が出る(MineColonies の飾りの建築と同じ。材料は建築家が求める)。手で組んでもよい。建造中は、同じページで型を替えたり、建造をやめたりできる。頼めるのは、コロニーの小屋を管理できる人。**機体ブロックそのものは、建造に関わらない**(置いても、素手で使っても、何も始まらない。燃料を手で入れる働きは残る)。窓から頼みを送るのは `network/AircraftOrderPayload`、受けるのは `flight/Shipyard.request()`・`stop()`。設計のブロックが全部そろうと、全体が船になり、台の向きに回って、固定される(機首を東に向けて建て、船になる時に回す)。
- **台の向きのまま建てる**(0.11.5)。建築家への依頼の設計図を台の向きに回し、そろったかも回した形で見る。設計は機首を東に向けて書いてあるので、完成の瞬間に同じティックの中で東向きに並べ直して船にし、台の向きへ戻す(`Shipyard.layNoseEast`)。
- 建築家が手を付けている間は、そろっていても船にしない(建築家が終えてから)。建造中の台には、ほかの機体は降りない。
- **命令で出す**こともできる(`/airline aircraft spawn`。試すとき用。燃料は満タンで出る)。建造した機体の燃料槽は、空で始まる。
- **整備(自動修復)。** (0.12.1 から: オン/オフのボタンは外した。飛行場は、母港にいる自分の機体を、いつも型どおりに戻す。型を直すのは**改修の道具**で: 世界ごとの設定 `saves\<世界>\serverconfig\airline-server.toml` の `designTools = true` の世界だけ、`/airline design start <村> [型]` → 手で改修 → `/airline design capture <村> <名前>`(ゲームのフォルダの `airline-designs\<名前>.json`)→ `/airline design end <村>`。型の決まりの文書は `src\main\resources\airline_docs\`(jar の中では `airline_docs/`)。手で置いた機体ブロックには、MOD は手を出さない。以下は 0.11 のころの書き方。)飛行場の窓の「機体」のページで、オン/オフできる(0.11.5。既定はオン。オフのあいだは何もしないで、部品が欠けていても飛ぶ)。オンのとき、母港に止まっている機体を、10 秒に 1 回、設計と見比べる。外寸の中に足されたブロックは外して回収箱へ、向きの変わった機械は戻し、無くなったブロックは飛行場の棚の同じブロックで付け直す。棚に無い部品があると、村の管理者に知らせて、**そろうまで飛ばない**。

### 燃料、遭難と救助

- **燃料庫**(0.11.6。ユーザーの裁定)。燃料は、機体ブロックのインベントリ(9 枠。燃料だけが入る)に、品物のまま持つ。機体ブロックを素手で使うと開く。エンジンは、燃料庫から 1 個ずつ取り出して燃やす。燃料槽(下)の量は「燃料庫の中身と、取り出して燃え残っている分」の合計。機体ブロックをプレイヤーが壊すと、中身はその場に落ちる。
- **燃料槽。** 機体ブロックが持つ。入れた燃料は「エンジン 1 基が燃やせる時間」で数える(石炭・木炭 1 個で 80 秒)。満タンは飛行 80 分ぶん(設定 `fuelCapacity`)。受け付けるのは、石炭・木炭・石炭ブロック(設定 `fuelItems`)。
- **燃えるのは、飛んでいる間だけ。** 飛んでいる間、燃料槽からエンジン 2 基へ少しずつ送り、着陸したら、燃え残りを燃料槽へ戻す。台の上では何も燃えない。
- **補給。** 飛行場の棚に燃料があれば、飛行士が機体まで運んで入れる(燃料槽が 3/4 を切ったら、満タンまで)。機体ブロックを、燃料を持って使っても入る。飛行場は、機体が燃料不足で、棚の燃料が少ないとき、村へ燃料を頼む(設定 `fuelStock`)。
- **便の前の確かめ。** 便の全部を飛ぶ時間 × 2 基 × 1.5 + 2 分ぶんが無ければ、便を出さない。
- **遭難。** 飛んでいる間に燃料が尽きたら、その場に固定されて止まる(落ちない。飛行士は席に着いたまま)。村の管理者に、座標と、要る燃料の目安を知らせる。
- **救助。** プレイヤーが機体まで行き、機体ブロックを、燃料を持って使う。残りの道のりに足りる燃料が入ったら、便を続ける。

### 定時便(荷の便)

**村 B の不足を、村 A の余りが、命令なしで空路で埋める。**

- **便は定時便だけ。** 機体は、着陸するたびに、Minecraft の 1 日(24000 ティック)停泊する。その間に、飛行士が荷を積み降ろしする。
    - 母港: 輸出用の棚に、ある村が欲しがっている品物が来たら、すぐ積み始める(行き先は、その時いちばん多く運べる村のうち、**降りられる台がある村**。その停泊の間は変えない。降りる台は、このとき決めて、取っておく)。1 日たって、積む物が無くなったら出る。積み込みが終わっていなければ、終わるまで延ばす。運ぶ物が何も無ければ、出ない。
    - 行き先: 降ろして、母港の欲しい品物がその飛行場の輸出用の棚にあれば積む。1 日たったら、荷が無くても帰る。
    - 母港でベッドに入っている飛行士は、起こさない(荷役も出発も、起きるまで待つ)。
- **飛行士が運ぶ。** 棚で品物を持ち、機体のそばまで歩き、荷室へ入れる(降ろすときは逆)。一度に同じ品物を 4 スタックまで。行き先でも同じで、運ぶ物が無い間は機体の席で待つ。
- **輸入用がいっぱいのとき。** 降ろせる分だけ降ろし、残りは、配達人が回収箱を空けるのを停泊が終わるまで待つ。それでも降ろせない分は、積んだまま帰り、母港の輸出用の棚に戻る。
- **届けすぎない。** 積んだ分(飛行士が棚から取った時点から)は、台帳の「向かっている分」に入り、その村の「欲しい」から引かれる。集積も、これを引いた数で数える。
- **取りに行くだけの便。** 届ける荷が無くても、相手の飛行場の棚に、母港の欲しい品があれば、空で飛んで取ってくる(届ける荷のある便が、いつも先)。相手の棚を見られるのは、相手の飛行場が読み込まれている間だけ。
- 決まりと数字は `flight/Cargo.java` にあり、`config/airline-cargo.toml` で変えられる。主なもの: `berthTicks`(停泊の長さ。既定 24000)、`pilotCarries`(false にすると、だれも運ばずに荷が移る。3 秒に 1 スタック)、`carryStacks`(飛行士が一度に持つスタック数)、`quietSeconds`(取り消しのあと、次の便の支度を始めるまで。既定 600)。

### 途中で何か起きたとき

- **台の上で機体の制御に内部の誤りが出ても、機体は台に残る。** いる場所の記録を持ったまま止まり、30 秒休んでから続きを動かす。荷を積んでいたら、降ろす段へ回る(母港で出発の前なら、荷を輸出用の棚へ戻して欠航)。空中での誤りは、その場に固定して終わりの状態(`STRANDED`)にする。
- **荷を積んだ便が途中で終わったら、台帳の「向かっている分」を引く。** 荷は荷室に残り、同じ品物は、また集められて送られる。
- **飛行士が運んでいる途中の荷は、機体のブロックに書き残す。** サーバーを止めても、続きから運ぶ。飛行士がいなくなったら、その分を台帳から引く。
- **飛行士が歩いて着けないとき**は、60 秒であきらめて、その場から受け渡す(管理者に知らせる)。飛行士の持ち物がいっぱいで持てないときは、その分を、だれも運ばずに移す(管理者に知らせる)。
- **行き先で飛行士が席に着けなかったとき**(いなくなった、歩いて着けない)は、荷を清算して、機体は台で待つ。飛行士と経路がそろいしだい、自分で母港へ帰る。20 分たっても帰れなければ、管理者に知らせる。
- **便の表に無い荷が荷室に残っていたら**(途中で終わった便の荷)、母港で、次の便の支度の前に、飛行士が輸出用の棚へ戻す。
- **便の間は、そのディメンションにプレイヤーが居なくても、機体の制御を止めない。**

### 村人が止まっている船の上を歩く(pathing)

2026-11-05 の 0.21.0 で、ColonyPatch Server から移した(空路を一般公開するにあたり、空路だけで動くように。中身は ColonyPatch Server 1.4.0 と同じ)。設定は `saves/<世界>/serverconfig/airline-ships.toml`、命令は `/airline board`・`/airline leave`・`/airline boarding`。Sable が入っているときだけ働く。

停泊中の船(Create Aeronautics の船)に村人が乗り込み、降りられずに立ち往生する問題への対処。

MineColonies の経路探索は独自の実装で、ワールドのチャンクを直接読む。Sable の船のブロックは別の場所に置かれているので、村人から見ると船は空気でしかない。物理的には甲板に立てるので乗ってしまうが、そこから歩いて降りる経路を考えられなかった。

本 MOD は、止まっている船のブロックを、ワールドの座標に置かれているものとして経路探索に見せる。

- 探索があるマスを読むとき、そのマスの中心を船の座標へ直し、一番近い船のブロックを返す。船が斜めを向いていても、半端な位置にあっても働く。
- 経路の点はワールドの座標のままなので、MineColonies の探索、歩行、行き詰まり処理はそのまま動く。
- 歩いている最中に船が動いたら、その経路を捨てる。動いている船に乗っている村人は、船が止まるまで待つ。

#### 使える船、使えない船

| 条件 | 扱い |
| --- | --- |
| 止まっていて、傾きが 5 度以内 | 経路に使う。向きと位置は問わない |
| 5 度を超えて傾いている | 使わない(空気として扱う) |
| 動いている | 使わない |

向きが 90 度の倍数から 5 度以内の船では、はしご・つた・開いた落とし戸も使える。それ以外の船では、ただのすき間として扱う。閉じた扉は、どの船でも通れないものとして扱う。

#### 停め方の注意

村人が歩いて乗り降りできるのは、次の両方を満たすときである。

- **船と地面が、すき間なく隣り合っている。** MineColonies の経路探索には横に跳ぶ動きが無いので、1 ブロック以上のすき間は越えられない。
- **段差が、村人の跳べる高さに収まっている。** 甲板と地面の実際の段差が約 1.2 ブロックを超えると、乗り降りできない。桟橋と甲板の高さをそろえるか、段を刻んでおく。

満たさない船に乗ってしまった村人は、今までどおり MineColonies の行き詰まり処理に任せることになる。

#### pathing の設定

`saves/<世界>/serverconfig/airline-ships.toml` の `[pathing]` の節(世界ごとの設定)。

| キー | 既定 | 意味 |
| --- | --- | --- |
| enabled | true | 機能の有効化 |
| stoppedPositionTolerance | 0.01 | 「止まっている」とみなす位置のずれ(ブロック) |
| stoppedAngleToleranceDegrees | 0.1 | 「止まっている」とみなす向きのずれ(度) |
| stoppedTicks | 20 | 上の幅に収まった状態が、何ティック続けば止まっているとするか |
| maxTiltDegrees | 5.0 | これを超えて傾いた船は使わない |
| discardMoveTolerance | 0.2 | 歩いている最中に、これから通る経路の点が船の動きでこれ以上ずれたら、経路を捨てる(ブロック)。止まっていた船を「動いている」に戻す幅も兼ねる(船の範囲の角のうち、一番動いた角で測る)。上限は 0.29 |
| alignedYawToleranceDegrees | 5.0 | 向きが 90 度の倍数からこの幅に収まる船では、はしごなどを使える |
| snapshotRefreshTicks | 20 | 船のブロックの写しを作り直す間隔(ティック)。船のブロックを変えても、この間は古い形で見える |
| maxShipVolume | 500000 | ブロックの範囲がこのマス数を超える船は使わない |
| logDecisions | false | 船を使い始めた・やめた、経路を捨てた、をサーバーログに出す(`[Airline/pathing]` で検索) |

捨てる幅は、止まっている幅より緩くしてある。村人が乗っただけの揺れで、自分の経路を捨ててしまわないためである。一方で、村人の体の幅の半分(0.3)より小さくしてある。経路の点が甲板の縁の真上にあっても、体が甲板に掛かったままになるようにするためである。

#### pathing の既知の限界

- 動いている船、5 度を超えて傾いた船は対象外。
- 船の扉は開けられない。
- 歩いている最中に船のブロックが変わっても、すぐには反映されない(写しの作り直しを待つ)。
- **斜めを向いた船では、歩けない場所が残る。** 床として見えるのは、マスの中心が本当の甲板の上にある場所だけなので、縁のマスの一部は歩けない。幅 1 の細い板は、向きが 20 度以上ずれると経路がつながらない。
- 斜めの甲板の縁や角のごく近くに立っている村人は、歩き出すときの出発点を MineColonies 自身が決める。船の下に地面か水があると、甲板から落ちうる立ち位置がごくわずかにある(甲板の面積の 0.1% 以下という計算。試験では起きていない)。
- **世界のブロックの並びから半ブロックほどずれて着陸した小さな船では、村人が甲板から歩いて降りられないことがある。** 空路輸送の試験で、甲板の狭い小型機(3×5)が台に着陸したとき、6 回のうち 3 回で起きた。向きは 1 度以内にそろっていた。原因は切り分けていない。空路輸送の側では、着陸の前に位置を台の中心に合わせて避けている(合わせたあとは、8 回とも降りられた)。
- 村人が船の上の収納などを使う仕組みは、まだ無い(席に座ることは、下の boarding でできる)。
- 自動試験で確かめた。実際のワールドでの確認と、目視はまだしていない。長い船がゆっくり回る場面は、式とコードで確かめただけで、試験は無い。

### 村人が船の席に座って運ばれる(boarding)

村人を船に「乗せる」ための土台。村人が、止まっている船の上の席まで歩き、座り、船が動く間は席に座ったまま運ばれ、船が止まってから立って歩いて降りる。

村人が自分から船に乗りに行く機能ではない。乗せる・降ろすは、管理者の命令か、ほかの MOD(計画中の空路輸送)からの呼び出しで起こす。

- 席は、船の上の好きなブロックでよい。座り方は MineColonies の食堂の席と同じ(MineColonies の座り用の実体を使う)。Create の座席である必要はない。
- 席まで歩く経路は、上の pathing が引く。船が止まっていて、歩いて行ける場所にあることが条件になる。
- 座っている間、村人の仕事・食事・睡眠は止まる。降ろすと元に戻る。
- 新しい実体やブロックは足していない。参加する側には何も要らない。

#### 命令

管理者(権限 2 以上)用。

| 命令 | 働き |
| --- | --- |
| `/airline board <村人> <座るブロックの座標>` | 村人を席へ向かわせ、座らせる。座標は、座るブロックが今ワールドのどこに見えているか。自分が立っている甲板のブロックなら `~ ~-1 ~` |
| `/airline leave <村人> [<地面の座標>]` | 立たせる。座標があれば、そこまで歩かせる。船が動いている間は断る |
| `/airline boarding <村人>` | 今の状態を答える |

村人の指定は、バニラの実体の指定(`@e[type=minecolonies:citizen,limit=1,sort=nearest]` や UUID)。

#### boarding の設定

`saves/<世界>/serverconfig/airline-ships.toml` の `[boarding]` の節(世界ごとの設定)。

| キー | 既定 | 意味 |
| --- | --- | --- |
| enabled | true | 機能の有効化。切ると、座っている村人を全員、甲板に立たせる。Sable と `[pathing] enabled` が要る |

#### ほかの MOD から呼ぶ入口

`com.asteain.airline.boarding.Boarding` の `available`・`board`・`boardAt`・`leave`・`state`。サーバーのスレッドから呼ぶ。Sable が無い環境でも呼べて、そのときは「Sable が無い」と答える。くわしくは [design/boarding-2026-10-06/opus-implement.md](../ColonyPatchServer/design/boarding-2026-10-06/opus-implement.md)。

#### boarding の既知の限界

- **降ろすまで座り続ける。** 時間切れは無い。座らせたまま忘れると、その村人は働かない。
- **動いている船では降ろせない。** 船が止まってから、降ろす命令をやり直す。
- **席が埋まっているかを見ていない。** 同じ席へ 2 人向かわせると、重なって座る。
- **進み具合は保存されない。** サーバーを普通に止めれば、保存の前に村人は甲板に立つ。異常終了だと、座ったまま保存される。読み直したあと、席は 5 秒ほどで消え、村人は甲板の上面より少し下(約 0.65)に降ろされる。Sable が甲板の上へ押し出す見込みだが、試していない。
- **座らせたまま遠くへ飛ばす船には、読み込みの印が要る。** 席は、船の中ではなくワールドの側に置いてある。Sable の読み込みの印(`addForceLoadTicket`)が付いた船は、船のまわりのワールドも読み込むので、座った村人は一緒に運ばれる(4〜5 チャンク先まで確かめた)。印が無い船は、読み込みの外で凍り、座っていた村人は自宅へ戻される(落ちない)。ただし、村人のいるチャンクが船より先に読み込みから外れる順番は確かめていない。その順番では、村人が空中に取り残されるおそれがある。印を付ける仕組みは、この MOD にはまだ無い(空路輸送の MOD で作る)。
- **船が消えたとき、逃がす先が見つからないことがある。** 順に、席の近くの地面、乗り込みを頼まれたときに立っていた地面、自宅を探す(自宅へ戻る所まで確かめた)。甲板の上から乗り込み、家も無い村人は、どれも無いので、その場に残る(下が虚空なら落ちる)。
- 経路探索を切っている、または止まっているときは、乗せることも降ろすこともできない。座っている村人を立たせるには、`[boarding] enabled` を切る。
- 立たせる場所は、席の隣の空いた甲板(1.2.1 から)。席のまわり 8 マスに立てる所が無ければ、席のブロックの上面に立たせる。そこの上にブロックがあると埋まる。
- 乗り込みの自動試験(`runShipBoarding`)で確かめたのは、無職の村人 1 人、板の甲板、無重力で固定した船である。そのあと、空路輸送の実機検証で、重力のある世界を飛ぶ小型の船でも確かめた。村人は、Create の座席まで歩いて座り、離陸、直進、旋回、着陸を通して座ったままだった(席からのずれは最大 0.06 ブロック、機体が 27 度傾いているとき)。
- 同じ検証で、着陸して固定した船への乗り降りも確かめた。2 つの発着場を往復する場面で、歩いて乗る・座る・立つ・歩いて降りるが 8 回とも通った。世界のブロックの並びに対して 12・30・45 度斜めに止まった船でも、乗り降りできた(1.2.0 では、斜めに止まった船で降りられないことがあった。1.2.1 の直しと、席を甲板の縁から内側へ置くことで解消した)。
- **席は、甲板の縁に置かないほうがよい。** 席のまわりに、村人が立てる甲板を 1 マス以上あける。
- まだ確かめていないこと:仕事を持つ村人、複数の村人、異常終了のあとの読み直し、目視。

## 命令(管理者用、権限レベル 2)

村の番号は、命令を実行したディメンションでの番号。

| 命令 | 働き |
| --- | --- |
| `/airline want add <村の番号> <品物> <個数>` | その村が空路網に品物を要求する(台帳に載せる) |
| `/airline want remove <村の番号> <品物>` | 要求を外す |
| `/airline want list` | 台帳の中身 |
| `/airline want clear [村の番号]` | 台帳を消す(番号を省くと全部) |
| `/airline export set <村の番号> <品物> <スタック数>` | その村の飛行場の輸出の表に行を足す(窓のタブと同じ) |
| `/airline export remove <村の番号> <品物>` | 行を外す |
| `/airline export list <村の番号>` | 表の中身 |
| `/airline net list` | 空路網の地点と航路と状態 |
| `/airline net blocked` | 塞がっている航路と、そのブロックの場所 |
| `/airline net route <地点の座標> <地点の座標>` | 経路 |
| `/airline net recheck` | 全部を調べ直す |
| `/airline aircraft spawn <村の番号> [型]` | その村の飛行場の台に、新しい機体を出す(型を省くと小枝号 `koeda`。燃料は満タン) |
| `/airline aircraft designs` | 機体の型の一覧 |
| `/airline aircraft list` | 読み込まれている機体と、それぞれの状態 |
| `/airline aircraft clear` | 空中であきらめた機体(状態 `STRANDED`)を片づける。**読み込まれている機体だけが相手**なので、近くまで行ってから打つ。荷室の中身は、打ったプレイヤーの持ち物に入る。席に残っていた飛行士は、乗り込んだ場所へ戻される |
| `/airline aircraft forget <村の番号>` | 時刻表から、その村の飛行場の機体のうち、いま読み込まれていないものを消す。機体が片づけの命令を通らずに消えてしまい、台が「母港」として取られたままになったときに使う。まだ存在する機体は、読み込まれたときに時刻表へ戻る |
| `/airline flight send <出発の村> <行き先の村>` | 試し打ち用。出発の村の飛行士が、母港の台の機体で、行き先の飛行場の空いている台まで飛ぶ(片道。荷なし。停泊の時計を待たない)。空いている台が無ければ断る |
| `/airline flight round <出発の村> <行き先の村>` | 同じ。着いたら 10 秒待って帰ってくる |
| `/airline flight status` | 機体ごとの状態と荷、**時刻表**(読み込まれていない機体も)、これまでの便の記録 |
| `/airline flight cancel [村の番号]` | いま出ている便を取り消す。便がいくつも出ているときは、機体の母港の村の番号を付ける。空中(行き)なら出発地へ戻る。離陸の前なら出発をやめ、荷(飛行士が持っている分も)を輸出用の棚へ戻す。**行き先に着いたあとなら、荷役をやめて、すぐ母港へ帰る**(荷室に残った荷は、母港で輸出用の棚へ戻る。命令で出した試し打ちの便が折り返しを待っているときは、その台で終わる)。取り消したあとは 10 分、次の便の支度をしない |

## まだ無いもの

旅客(プレイヤーが乗る席、酒場の来訪者)、複数の村を回る便、所属機を増やす仕組み(駐機場、空中の係留)、機体を建造する画面(いまは、機体ブロックを置いて始める)、研究での解禁。空路用の外交の表は、将来の検討に回した(2026-10-11 の裁定)。

## MOD を外すとき

外しても、ワールドは開き、村は使える(`runAirfieldRemoved` で確かめた)。飛行場の建物と小屋ブロック、飛行士の職は消える。棚と回収箱とその中身は残る。そのために、依頼の仕組みの保存データにこの MOD の名前が入らない作りにしてある(`PilotWorkModule` の注記を参照)。

## ビルドと試験

MineColonies などの jar は、このプロジェクトには置いていない。隣の `..\ColonyPatchServer\libs`(コンパイル用)と `..\ColonyPatchServer\test-jars`(試験用サーバーの mods)を相対の道で使う。Gradle はオフラインで動かす。

```
python tools/run_gradle.py run-logs/build.log build
python tools/run_gradle.py run-logs/airfield.log --timeout 1500 runAirfield
python tools/run_gradle.py run-logs/cargo.log --timeout 1800 runFlight -Pscene=cargo
python tools/run_batch.py <札> runAirfield runAirfieldReload runAirfieldRemoved runNetwork trip far cargo carry traffic three detour
python tools/run_batch.py <札> --sprint all
python tools/run_batch.py <札> --sprint --part 2/3 all
python tools/run_split.py <札> --sprint Airline-testcopy Airline-testcopy2
```

- **サーバーを起動するタスク(名前が `run` で始まるもの)は、必ず `tools/run_gradle.py` を通す。** 全部のプロジェクトと写しを合わせて同時に 2 つまで動くように、順番待ちの札を ColonyPatchServer と共有している(札の場所は `..\ColonyPatchServer\run-logs\server-slot.lock` と `server-slot-2.lock`。ColonyPatchServer の側は 1 枚めだけを使う)。2 つまでにしているのは、前にメモリが尽きたことがあるため(サーバー 1 つで 3 GB まで、Gradle も 3 GB まで)。2 枚めの札で起動したサーバーは、待ち受けの番号を 100 上げる。写しごとの札(`run-logs\copy.lock`)も取るので、同じ写しで 2 つは走らない。
- `tools/run_split.py <札> [--sprint] <写し 1> <写し 2>` は、ソースを 2 つの写しへ写してから、全部の場面を掛かる時間の見込みで 2 つに分け、2 つの写しで同時に回す(2026-10-15)。最後に合計の行を出す。
- `tools/run_batch.py` は、何本かを続けて回し、結果を `run-logs\<札>-<名前>-result.txt` と `<札>-summary.txt` に残す。場面の名前のあとに `@<型>` を付けると、その型の機体で飛ばす(`trip@koeda`)。項目に `all` と書くと全部の場面(37 本)。`--part 2/3` で、全体を 3 つに分けた 2 つめだけを回す(続きの reopen は分けない)。最後に合計の行を書く。
- **早回し `--sprint`**(2026-10-15): サーバーが刻みを追いつく限り速く進める(Minecraft の tick sprint)。全部の場面が、普通の速さで 3 時間あまりのところ、40 分ほどで終わる見込み(2026-10-15 の札 sp3〈reopenc 以外の 32 本〉と sp5〈reopenc の 4 本〉からの見積もり。項目数は同じ。うち 9 分ほどは、1 本ごとに順番待ちの札を譲る 15 秒)。場面の中で起きることは刻みの数で決まるので同じだが、地形の読み込みや MineColonies の道探しは刻みと別に進むので、早回しではそれを待つ刻みが増える。そのため試験の待ち(`until`、`attempt`、見張り)は、刻みの数に加えて、普通の速さなら掛かる時間も過ぎるまで諦めない。新しく作った機体は、読み込まれてから先へ進む。reopen の場面は、早回しでも普通の速さで回る(早回しのまま止めると、止める途中で回り続けて終わらないことがあった)。
- `tools/sync_copy.py <写しのフォルダ> ...` は、ソースと道具を、試験用の写しへ写す。サーバーの順番待ちの札を取ってから写すので、その写しで試験が走り始める瞬間に、ソースが入れ替わることがない。
- **試験が走っている間に、同じフォルダでビルドしない**(走っているサーバーが読むクラスを書き換えてしまう)。長い試験は、プロジェクトの写し(`src`、`tools`、Gradle のファイルだけを隣のフォルダへ写したもの)で回すと、本体で作業を続けられる。
- 試験用 MOD(`src/testmod`、ID `airlinetest`)を専用サーバーで動かす。プレイヤーはいない。結果は各実行フォルダの `airline-result.txt`(`PASS <項目数> ...` か `FAIL ...`)。
- 村人が船の上を歩く・席に座る部分の試験は、もう 1 つの試験用 MOD(`src/shiptest`、ID `shiptest`)。2026-11-05 に ColonyPatch Server から移した。タスクは `runShipSmoke`(MineColonies・Sable・Create の同居)、`runShipPathing`・`runShipPathGrid`・`runShipShips`・`runShipMotion`・`runShipReach`・`runShipEdge`・`runShipEdgeLand`・`runShipLandWalk`・`runShipLandHeight`(歩行)、`runShipLanding`・`runShipBurner`・`runShipMooring`・`runShipMooringGravity`(止まっているかの判定)、`runShipBoarding`(乗り込み)、`runShipLab`(調べ物。合否はほとんど見ない)。実行フォルダは `run-ship-<名前>/`、結果は `ship-result.txt`(`XPASS` は失敗)。一覧は `build.gradle` の `shipChecks`。
- `runAirfield` → `runAirfieldReload` → `runAirfieldRemoved` は、この順で回す(同じワールドを使う。最後のものは、この MOD のコードなしで起動して、ワールドが開くかを見る)。`runNetwork` は、ブイの網だけ(何も飛ばない)。
- `runFlight -Pscene=<名前>` の場面:
    - 飛ぶだけ: `trip`(往復、封鎖、欠航)、`far`(710 ブロックの片道)、`direct`(大マップをまたぐ 1,815 ブロックの直行便。ブイなし)、`faults`、`crash`、`reopen1` → `reopen2` → `reopen3`(飛行中と着陸中にサーバーを止めて開き直す。この順で続けて回す)。
    - 2 機以上: `traffic`(レベル 1 と 2 の台の決まり、向かい合わせに同時に出した 2 機、1 つの台を取り合う 2 便、取り消しの指定)、`three`(三角に並んだ 3 つの村から、3 機を同時に出す)、`detour`(航路の上に止まっている船を、待ってから迂回する)。
    - 荷の便で、飛行士が運ぶもの: `cargo`(命令なしで村 B の不足が埋まるまで。停泊と時刻表も見る)、`carry`(運んでいる途中の取り消し、輸入用がいっぱい、行き先での取り消しと、母港での荷室の片づけ)。
    - 荷の便で、荷がひとりでに移るもの(`pilotCarries` を切って、飛ぶ所と台帳と命令を見る): `ground`、`lost`、`hindered`、`reopenc1` → `reopenc2` → `reopenc3` → `reopenc4`。
    - 試験では、停泊を 300 ティック(`cargo` だけ 1200 ティック)に縮めている。
- 配布する jar(`build/libs/`)に試験用のクラスは入らない。

## 名前について

2026-10-07 に改名した。旧名は Air Route / `airroute`(命令は `/airroute …`、パッケージは `com.asteain.airroute`、試験用 MOD は `airroutetest`)。いまの名前は Create Aeronautics: Airline for MineColonies / `airline` で、ID から作っている名前は全部これに合わせて変わった(ブロックと建物と職業の登録名、建物モジュールのキー、台帳と空路網の保存データ、設定ファイル、読み込みの印の型、翻訳のキー、設計図のパック「Airline」)。古い名前のワールドや設定は読めない(本番には入れていなかったので、移すものは無い)。設計図の中にも ID が入っているので、ID を変えたら `python tools/make_blueprint.py <ID>` で作り直す。プロジェクトのフォルダの名前は、2026-10-11 までに `Airline` に変わった。
