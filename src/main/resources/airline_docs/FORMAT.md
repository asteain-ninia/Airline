# 設計ファイルの書式と、機体が満たす決まり

設計は JSON 1 つです。試験場(`tools/bench.py`)も、最後に空路 MOD へ入れるときも、このファイルをそのまま読みます。

## 座標

- **原点 (0, 0, 0) は「機体ブロック」**(`airline:aircraft`。この MOD の操縦ブロック。立方体、質量 1.0)。甲板の真ん中の 1 ブロックです。**設計ファイルには書きません**(自動で置かれます)。
- **機首が +x**、上が +y、**右舷が +z**(左舷が −z)。
- **外寸は、機体の級(`class`)で決まる箱の中**(2026-10-15 から。級は 3 つ)。1 ブロックも出せません。発着場の台、台と台の間、航路の管の太さが、この箱で作ってあるためです。

| 級 `class` | x(前後) | y(高さ) | z(左右) | 大きさ | 降りられる所 |
| --- | --- | --- | --- | --- | --- |
| `small`(小型機。小枝号、こかぜ) | −4〜4 | 0〜9 | −4〜4 | 前後 9 × 左右 9 × 高さ 10 | 小型飛行場、中型飛行場 |
| **`medium`(中型機)** | **−7〜7** | **0〜12** | **−5〜5** | 前後 15 × 左右 11 × 高さ 13 | 中型飛行場、大型飛行場、泊地 |
| `large`(大型機) | −12〜12 | 0〜16 | −7〜7 | 前後 25 × 左右 15 × 高さ 17 | 大型飛行場、泊地 |
- **ブロックどうしは、面でつながっていなくて構いません**(2026-10-14 から)。空路 MOD は、設計のブロック全部を、まとめて 1 つの船にします。船は、自然には壊れません(手本の STRATUS は、26 個が面でつながっていないまま、組み上がって飛びました)。**形を保つためだけのブロック(柱、梁、支え)は、要りません。** `tools/check.py` は、つながっていない所を「知らせ」として出すだけです。ただし、レバーなど、何かに付けて置くブロックは、付く相手が要ります(付く相手が無いと、組み立てで落ちます)。
- y = 0 の層が、台の床の上に載ります(機体は、いちばん下のブロックで台に着きます)。y = 0 より下は使えません。

## 書式

```json
{
  "format": 2,
  "class": "medium",
  "blocks": [[x, y, z, "名前空間:ブロック[状態=値,状態=値]"], ...],
  "seat": [x, y, z],
  "cargo": [[x, y, z], [x, y, z]],
  "access": [[x, y, z], ...],
  "passengers": [[x, y, z], ...],
  "burners": [{"at": [x, y, z], "lever": [x, y, z], "value": 80}],
  "engines": [[x, y, z], ...],
  "levers": {"好きな名前": [x, y, z], ...},
  "drive": {
    "ahead":       {"レバーの名前": 15, ...},
    "astern":      {...},
    "left":        {...},
    "right":       {...},
    "ahead_left":  {...},
    "ahead_right": {...},
    "ahead_slow":  {...},
    "astern_slow": {...},
    "left_slow":   {...},
    "right_slow":  {...}
  },
  "throttles": ["レバーの名前", ...],
  "handling": {"climbRate": 1.0, "throttleStep": 2}
}
```

| 項目 | 中身 |
| --- | --- |
| `class` | 機体の級(`small`、`medium`、`large`)。書かなければ `small` |
| `blocks` | 機体のブロック全部(機体ブロックを除く)。状態は、`/setblock` に書くのと同じ形(`create:shaft[axis=x]`)。書かなかった状態は、そのブロックの既定値 |
| `seat` | 飛行士の席(`create:<色>_seat`)の位置。1 つ |
| `cargo` | 荷室の樽(`minecraft:barrel`)の位置。**2 つ以上** |
| `access` | 樽の荷を出し入れするときに、人が立つマス(足のあるマス)。樽ごとに、同じ高さの隣に 1 つ要る |
| `passengers` | 任意。客の席(`create:<色>_seat`)の位置。プレイヤーが台の上で座って乗る(便は客を待たない)。**飛行士の歩く所(登り口・席・`access` を結ぶ道)から離して置く**: Create の席は、上を歩いた村人を座らせる(飛行士が座らされたら、MOD が降ろす)。小枝号は機首の両脇に 2 席(2026-10-17) |
| `burners` | 熱気バーナー(`aeronautics:adjustable_burner`)と、その隣のスロットルレバー、バーナーの出力の設定値(5〜500。`value`)。1 つ以上 |
| `engines` | 携帯エンジン(`simulated:<色>_portable_engine`)の位置。**1〜4 台**。ここに書いたエンジンにだけ、燃料が配られる |
| `levers` | 推進を操るスロットルレバー(`simulated:throttle_lever`)。数は自由。名前は自由 |
| `drive` | 操作ごとに、どのレバーをいくつ(0〜15)にするか。書かなかったレバーは 0。上の 6 つは必ず要る。`_slow` の 4 つは任意(下の「細かく合わせる」) |
| `throttles` | 任意。`levers` の中で、**少しずつ動かしてほしいレバー**の名前(下の「スロットル」) |
| `handling` | 任意。設計の側で決められるのは、`climbRate`(上昇のとき、目標の高さを毎秒何ブロックずつ上げるか。既定 1.0)と、`throttleStep`(スロットルを、1 回の判断で何段まで動かすか。既定 2)。ほかの操縦の数字は、試験場が測って決める |

## 自動操縦との約束(これが「空路 MOD に対応する」の中身)

自動操縦は、**スロットルレバーの値を書くことしかしません**(プレイヤーが手でできることと同じ)。機体を押したり、ブロックの中身を書き換えたりは、しません。

- **高さ:** バーナーのレバー全部に、同じ値(0〜15)を書いて保ちます。10 ティックに 1 回、値を見直します。
- **推進:** 10 ティックに 1 回、次の 6 つの操作のどれか(か、全部 0 の「切」)を選び、`drive` の表のとおりにレバーを書きます。細かく合わせるときは、2〜9 ティックだけ入れて、すぐ切ります。

| 操作 | 機体に起きてほしいこと |
| --- | --- |
| `ahead` | 機首(+x)の向きへ進む |
| `astern` | 後ろ(−x)へ進む。止まるときの制動にも使う |
| `right` | **その場で**右へ回る(上から見て時計回り。機首が +z のほうへ向く)。前後へは、なるべく動かない |
| `left` | その場で左へ回る |
| `ahead_right` | 前へ進みながら、ゆるく右へ向きを変える(巡航中の、数度の修正) |
| `ahead_left` | 前へ進みながら、ゆるく左へ |

- 切にしたら、押す力も回す力も残らないこと。**切は、ふつうは「全部のレバーが 0」です。** 0 では切れない作り(信号 15 で切れる部品など)なら、`drive` に `"off": {"レバーの名前": 値, ...}` を書いて、切のときの値を決められます。地上に止まっている間も、レバーは切の値のままです。

### スロットル(少しずつ動かすレバー)

強い推進を、止まった所から一気に入れたり、巡航中に一気に切ったり逆にしたりすると、熱気球の機体は、前後に大きく傾きます(推力や抵抗が、重心とずれた高さに、急に掛かったり消えたりするため)。人が操縦するなら、スロットルを少しずつ動かす所です。

`throttles` に名前を書いたレバーは、自動操縦が、そのように扱います。

- 操作の表の値へ向けて、**1 回の判断(10 ティック)ごとに `throttleStep` 段ずつ**近づけます(上げるときも、下げるときも)。
- **`throttles` 以外のレバーが変わる操作へ移るとき**(前進 → 後進、前進 → その場の旋回、前進 → 切、など)は、**まず `throttles` を「切」の値まで下げてから**、ほかのレバーを切り替え、そのあと上げ直します。全開のまま逆転したり、全開からいきなり切れたりは、しません。
- `throttles` が「切」の値のままの操作(弱い操作など)どうしは、これまでどおり、すぐ切り替わります。短い押しで細かく合わせるのは、こちらです。
- 試験場の飛行試験は、この動かし方で測ります(加速・惰性・制動の時間と距離には、スロットルの上げ下げの時間が入ります)。台の上での回転数の読み取り(`turning`)だけは、一気に入れて読みます。

アナログ変速機につないだ「速さのレバー」のように、値で強さが変わるレバーに向いています。入り切りだけのレバー(ギアシフトやクラッチのレバー)は、書かないでください。

### 細かく合わせる(弱い操作)

台の真ん中に降りるには、位置を **0.2 ブロック**、向きを **1 度**まで合わせます。自動操縦は、操作を短く(最短 2 ティック)入れて合わせますが、**1 回の短い押しで動く量は、その操作の最高の速さに比例します**(最高が毎秒 v の操作を t 秒入れて切ると、惰性も含めて、合わせて v × t だけ動きます。回るのも同じです)。毎秒 6 ブロックの機体は、2 ティックで 0.6 ブロック動いてしまい、0.2 には合わせられません。

そこで、**速い機体は、弱い操作も用意してください。**

| 操作 | 機体に起きてほしいこと | 目安 |
| --- | --- | --- |
| `ahead_slow` | ゆっくり前へ | 最高で毎秒 1〜1.5 ブロック |
| `astern_slow` | ゆっくり後ろへ | 同じ |
| `left_slow` / `right_slow` | その場で、ゆっくり回る | 毎秒 10〜15 度 |

- 作り方は自由です(弱いプロペラだけを回す、遅い歯車の段へ切り替える、など)。
- 書かなければ、ふつうの操作(`ahead` など)が代わりに使われます。最高が毎秒 2 ブロック・毎秒 20 度ほどまでの機体なら、それで合わせられます。
- 自動操縦は、目標の近くと、台の上の位置合わせでは弱い操作を、遠いうちはふつうの操作を使います。止まるときは、`astern` を制動に使います(速い機体だけ)。
- **スロットルレバーは、触れているブロック全部に信号を出します**(6 方向)。バーナーに触れてよいレバーは、そのバーナーのレバーだけです(推進のレバーが触れると、進むたびにバーナーが全開になります)。レバーの置き方は [PARTS.md](PARTS.md)。
- エンジンは、飛んでいる間、止められません(燃料がある限り回ります)。推進の入り切りは、レバーで動く部品(ギアシフト、クラッチなど)でします。
- Create は、回転の入り切りがあまり続いた部品を壊します。自動操縦は 10 ティックに 1 往復までにしていますが、1 回の切り替えで大きな歯車列がまるごと逆転するような作りは、避けたほうが無難です。

## 人が乗り降りできること

飛行士は村人(Minecraft の人型。幅 0.6、高さ 1.8)で、台の床を歩いて来て、甲板に上がり、席に座ります。荷の積み下ろしも、飛行士が甲板と台を歩いて往復します。

- **甲板:** y = 0 が立方体のブロック、その上の y = 1 と y = 2 が空いているマスが、「立てるマス」です(レバーやカーペットのような、当たり判定の無いものは、あってもよい)。
- **登り口:** 甲板の縁の立てるマスで、そのすぐ外(機体の外側の隣の列)の y = 0〜2 に何も無い所。台の床から、1 段跳んで上がります。**1 か所以上。尾(x ≦ 0)の側に 1 か所は欲しい**(飛行士は尾の側から来ます)。
- **席:** 席の真上(y + 1)は空ける。席の前後左右のどれかに、登り口から歩いて行ける立てるマスがあること(座るとき・降りるときに立つ場所)。
- **荷室:** 樽ごとに、同じ高さの隣に立てるマス(`access`)があり、登り口から歩いて行けること。
- 歩く道は、立てるマスが前後左右につながっていること(1 段の上り下りは可)。
- **降り口を、1 マスだけにしないこと(2026-10-14 から)。** 機体は、台の真ん中から 0.3 ブロックほどずれて着くことがあります。ずれた向きの降り口は、機体の縁が隣のマスに食い込んで、飛行士が降りられなくなります(3 回目の設計で、実際に起きました。降り口が船尾の真ん中の 1 マスだけで、機体が前後に 0.33 ずれて着いた)。**船尾の列を横 3 マスとも立てる床にするか、前後と左右の 2 つの向きに降り口を持たせてください。**
- **熱気バーナーの上を、人の通り道にしないこと。村人は、バーナーの上に乗ると死にます**(往復の試験で、実際に起きました)。村人は、1 段の段差なら上って近道をします。席やバーナーのような、背の低い・1 ブロックの物は、踏み越えます。登り口(尾の側)と、席・`access` を結ぶまっすぐな線の上にバーナーがあると、踏みます。**甲板にバーナーを置くなら、席と `access` は、バーナーより尾の側(x が小さい側)に置いてください。**

### 横の降り口(中型機・大型機。2026-10-15 から)

中型機と大型機は、**泊地**にも泊まります。泊地には床がありません。島の縁から空中へ突き出した**桟橋**(幅 3〜4)の横に、機体が**空中で横付け**して止まり、飛行士は**横へ歩いて**桟橋へ降ります(依頼主の決めたこと:「桟橋の横に横付け」)。

- **甲板の幅 `r`** = y = 0 の層のブロックの、z の絶対値のいちばん大きい所(左右で同じにする)。泊地では、機体は、この甲板の端(z = ±r の列)が桟橋の縁にちょうど接するように止まります。**甲板の高さ(y = 0 の層)が、桟橋の床と同じ高さ**です。
- **両舷に、横の降り口を 1 か所以上**: z = +r の列と z = −r の列のそれぞれに、**立てるマス**(y = 0 が立方体、y = 1 と 2 が空き)が 1 つ以上あり、そのすぐ外(z = ±(r + 1) の、y = 1 と 2)に機体のブロックが無いこと。桟橋は、機体の前後 12 ブロックずつに続いているので、降り口は x のどこでも構いません。**両舷**なのは、泊地を鏡写しに建てると、桟橋が反対側に来るためです。
- 横の降り口から、席と、樽の `access` まで、歩いて行けること(台の上と同じ決まり)。
- 台(飛行場)の上では、これまでどおり、台の床から甲板に上がります(「登り口」)。中型機・大型機も、登り口は要ります。
- 降り口を 1 マスだけにしない決まり(上)は、横の降り口にも当てはまります。各舷 **2 マス以上**(前後に並んだ 2 マスなど)が勧めです(泊地では、機体が前後に 0.3 ほどずれて止まることがあります)。

### 連結器(中型機・大型機。2026-10-15 から)

施設の側には、Create Aeronautics の**連結器**(`simulated:docking_connector`。質量 1.0)が埋めてあり、泊まった機体の連結器とつながる予定です(つなぐ働きは、空路 MOD のこれからの仕事。いまは見た目と位置の約束だけ)。機体にも、次の位置に連結器を置いてください。

| 連結器 | 級 | 位置 | 向き(`facing`) |
| --- | --- | --- | --- |
| 横型(右舷) | 中型・大型 | **(0, 0, +r)**(機体ブロックの真横の、甲板の端) | `south`(外向き、+z) |
| 横型(左舷) | 中型・大型 | **(0, 0, −r)** | `north`(外向き、−z) |
| 下部 | **中型だけ** | **y = 0、z = 0 の中心線の上**(x は −3〜3 のどこか。0 は機体ブロックなので除く) | `down` |

- 状態は、どれも **`extended=false,powered=false`**(縮めたまま。伸ばすのは、空路 MOD が泊まったときにする)。
- **連結器に、レバーやレッドストーンの信号が届かないこと。** 信号が来ると、伸びます。スロットルレバーは、触れているブロック全部に信号を出すので、**連結器の 6 方向の隣に、スロットルレバーを置かない**。
- 横型の連結器は、甲板の端の列(z = ±r)の y = 0 にあるので、その列は、横の降り口(上)とは別の x に、降り口を作ってください(連結器の上には立てません)。
- 下部の連結器は、y = 0 の層にあって下を向きます。台の床に埋めた連結器の真上に来ます(台の側の位置は、あなたの選んだ x に、こちらで合わせます)。

`python tools/check.py <設計>` が、ここまでの決まりを(ゲームなしで)確かめます。

## つり合いと、浮く余裕

- **重心は、前後・左右とも、原点から 0.3 ブロック以内**(試験場の `centreTowardNose`・`centreToRight`)。ずれると、傾いて浮き、まっすぐ飛びません。
- **浮く余裕:** 試験場の高さ(y = 112 あたり)で、つり合うレバーが **9.5 以下**になるようにしてください(試験場の `hover.hoverLever`)。高い所ほど空気が薄く、同じ熱気で支えられる重さが減ります。村は、もっと高い所(y = 250 あたりまで)にも在りえます。バーナーの `value` と気嚢の広さで合わせます。
- 推進の力が、重心より高すぎる・低すぎる所に掛かると、進み始めと止まり際に、前後に大きく傾きます(試験場の `ahead.largestNoseUpOrDown`)。
- **気嚢の中に、機械を置かないこと**(依頼主のご指摘)。気嚢の中のブロックは、1 個につき 1 m³、容量を減らします(レバーや柵の柱も数えられます)。エンジン、歯車、変速機、切替ギア、レバーは、気嚢の下(ゴンドラ)に置き、プロペラへは、軸で回転だけを持ち上げてください。気嚢の壁を回転が抜ける所は、気嚢つきシャフト(`aeronautics:<色>_envelope_encased_shaft`。気密のブロックなので、漏れません)を使います。気嚢の中を通るシャフトは、通る長さのぶんだけ容量が減るので、なるべく短く。`tools/check.py` が、気嚢の中にあるブロックを数えて知らせます。

## 建てられること

この機体は、村の建築士が、設計図から 1 ブロックずつ建てます。プレイヤーが材料を用意します。

- **サバイバルで手に入り、ブロックとして置けるものだけ。** クリエイティブ専用の部品(`create:creative_motor` など)は使えません。
- **置いただけで働くこと。** 置いたあとに、人が手で設定したり、レンチで叩いたり、組み立ての操作をしたりは、できません(例外は、バーナーの設定値だけ。MOD が書きます)。プロペラ軸受けの帆は、回転が届くと自分で組み上がるので、使えます(PARTS.md の 13.3 に注意書き)。
- 何かに付いていないと置けないブロック(レバー、ランタン、カーペットなど)は、付く相手のブロックが設計の中にあること。置く順は、下の層から上へ、同じ層の中では立方体が先です。
- 柵・板ガラス・階段の、つながり方の状態は、書かなくて構いません(置いたあとに、隣を見て決まります。バニラのブロックだけ)。
