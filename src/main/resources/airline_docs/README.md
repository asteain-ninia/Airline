# 機体の型の決まり(空路 MOD「Create Aeronautics: Airline for MineColonies」)

この MOD は、自分で作った機体しか飛ばしません。ゲームの中で機体を手で改修しても、その改修は受け付けません。飛行場は、母港にいる自分の機体を、いつも型(設計)どおりに戻します。手で置いた機体ブロックは、ただのブロックです(2026-10-16 の作者の決まり)。

型を足したい・直したいときは、この文書を、お手元の AI エージェントに読ませてください。型は JSON のファイル 1 つで、決まりはこのフォルダの文書に全部書いてあります。

## このフォルダの文書

| 文書 | 中身 |
| --- | --- |
| `FORMAT.md` | 型のファイルの書式と、機体が満たす決まり(座標、級ごとの外寸、席・樽・降り口、バーナー、エンジン、レバーと操作の表、自動操縦との約束、乗り降り、連結器、つり合い、建てられること) |
| `PARTS.md` | 使える部品と、その働き(プロペラ、軸受けと帆、バーナーと気嚢、動力と変速、質量、推力と速さの見積もり) |
| `BENCH.md` | 試験場(本物の専用サーバーで、型どおりの機体を作り、レバーだけで動かして測る)の結果の読み方。操縦の数字(`handling`)は、試験場が測って決める。**無いと、自動操縦が止まる距離を見誤り、行き先を大きく行き過ぎる** |

この MOD の jar の中では `airline_docs/` に、ソースでは `src/main/resources/airline_docs/` にあります。

## 型を直す流れ(改修の道具)

ゲームの中で形を作ってから、それを型のファイルに取り込めます。**遊んでいない世界で使ってください。**

1. その世界の `saves/<世界>/serverconfig/airline-server.toml` で `designTools = true` にして、世界を開き直す(既定は使えない)。
2. `/airline design start <村> <型>`: その村の飛行場の台に、型どおりの機体を出す。この機体には「改修中」の印が付き、飛行場は直さず、便も出さない。その級を泊められる飛行場が要る(中型機は中型か大型の飛行場、大型機は大型飛行場)。飛行場にもう機体がいるときは、`/airline design start <村>`(型を書かない)で、その機体に印を付ける。
3. クリエイティブで、手で改修する。**機体ブロック(`airline:aircraft`)は壊さない**(壊すと、ただのブロックになり、取り込めない)。
4. `/airline design capture <村> <名前>`: 船のブロックを、機体ブロックからの相対位置(機首が +x)で、ゲームのフォルダの `airline-designs/<名前>.json` に書く。元の型のファイルの、ブロックの並びだけを差し替えたもの。回っているプロペラの羽根(ブロックでなくなっている)は、元の型のとおりに入れる。
5. `/airline design end <村>`: 印を外す(母港にいる間に、飛行場が元の型どおりに戻す)。

取り込んだファイルの、席・樽・降り口・バーナー・エンジン・レバーの位置、操作の表(`drive`)、操縦の数字(`handling`)は、元の型のままです。改修に合わせて直し、試験場で測ってください。

## MOD に型を入れる(ソースから作り直す)

1. 型のファイルを `src/main/resources/airline_aircraft/<名前>.json` に置き、`AircraftType` の `BUNDLED` に名前を足す。`title` の欄は入れない(名前は言葉のファイルで決める)。
2. 試験場で測る: `python tools/bench.py <型のファイル> --mode all --sprint`(結果は `run-logs/bench/` に)。結果の `handling` を、型のファイルの `handling` に書き写す。結果の `notes` が空で、自動操縦の課題(直進・旋回・位置合わせ)が通ること。
3. 建築士が建てる設計図を作る: `python tools/make_aircraft_blueprints.py`(全部の型の設計図を作り直す。変えていない型の設計図も中身が同じまま書き直されるので、git で戻してよい)。
4. 言葉: `assets/airline/lang/ja_jp.json` と `en_us.json` に `aircraft.airline.<名前>`。
5. ビルドして(`gradlew build`)、通しの試験を回す(`python tools/run_split.py <札> --sprint <写し 1> <写し 2>`、または `tools/run_batch.py`)。

## 決まりごとの要点(詳しくは FORMAT.md)

- 原点 (0, 0, 0) は機体ブロック。機首が +x、上が +y、右舷が +z。
- 外寸は級(`class`)の箱の中: 小型 前後 9 × 左右 9 × 高さ 10、中型 15 × 11 × 13、大型 25 × 15 × 17。1 ブロックも出せない(台、竪穴、航路の管が、この箱で作ってある)。
- 推進は、スロットルレバーの値だけで操れること(自動操縦はレバーしか動かさない)。操作の表に、前進・後進・その場の左右・進みながらの左右(と、あれば弱い操作)を書く。
- 前後と左右の重心は、機体ブロックの中心から ±0.3 以内。押す高さ(プロペラ)は、気嚢の中ほどに(低いと、全開で機首が上がり続けて宙返りする)。
- 飛行士が席まで歩けて、降りられること(降り口)。荷の樽の前に立てる所(`access`)。
